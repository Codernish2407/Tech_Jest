## Prioritized implementation checklist

No confirmed P0 finding in this reviewed batch. Findings below were established from current source and targeted reproductions; implementation and verification limits are recorded separately.

- [x] **P1 — Conversation history stops at 100 messages.** The messages endpoint sorts oldest first and limits to 100; polling therefore never shows later replies. It marks the entire conversation read using server wall time even when newer messages were not retrieved. Add bounded latest-page reads, older-history navigation, and a read cursor based on messages actually returned. Cover authorization, ordering, pagination, and conversation switches.
- [x] **P1 — Direct request writes trust client metadata.** Authenticated clients can supply `created_at` (bypassing the hourly count), supply catalog name/price snapshots, and exceed API field limits by calling Supabase directly. Request limits also count before inserting without serializing concurrent submissions. Prepare a non-destructive migration with database validation/canonical snapshots and serialized limits; preserve admin ownership rules and document rollout/rollback. Do not apply to production.
- [x] **P2 — Malformed API input.** Contact accepts JSON `null` then dereferences it; conversation creation treats invalid/missing JSON as a valid new thread. Validate object bodies and service selections before database work, and avoid returning database internals from admin errors.
- [x] **P2 — Build depends on Google Fonts availability.** Bundle the same verified local font assets and license notices; retain existing typography with bundled CSS and the original Unicode subsets/fallback metrics.
- [x] **P2 — Cart persistence failures.** Storage writes can throw when adding/removing services; a storage cleanup error after a successful quote is reported as a failed submission, inviting duplicates. Make cart persistence explicit and preserve success after the server accepts the request; cover blocked storage and cross-tab updates.
- [x] **P2 — Per-instance limiter grows under rejected traffic.** It appends another timestamp even for rejected requests and returns text to JSON callers. Bound counters and tracked addresses; return JSON with retry information. Keep database limits as the authoritative protection across instances.
- [x] **P2 — Runtime prerequisites.** `package.json` advertises Node 20 while the installed Vitest/Vite tooling requires newer versions; align the supported development runtime with the existing Node 22 pin.
- [x] Run local regression/type/format/build checks and record blockers. Browser/database integration execution remains pending; test discovery alone is not execution.
- [x] Review the final diff and update current-state/known-issues/setup and release notes.
